# COURT · 篮球专项训练 PWA

React + TypeScript + Vite，适配 Windows 与 iPhone。无需账户，所有训练记录只保存在设备的 IndexedDB；应用不含统计分析 SDK，不上传训练记录。GitHub Pages 提供静态资源；可选的 Cloudflare 推送服务仅接收通知订阅、随机设备凭证、提醒版本与到期时间。

## Windows 开发

安装 Node.js 24 LTS，再运行 `npm install -g pnpm@11`。进入项目目录：

```powershell
pnpm install
pnpm dev
```

也可双击 `启动训练应用.cmd`。开发地址仅供这台 Windows 使用。验证生产版离线能力：

```powershell
pnpm test
pnpm build
pnpm preview
```

开发模式不注册离线缓存。生产预览 http://127.0.0.1:4173 可以使用 Service Worker。

## 已内置的正式计划

“篮球专项训练”周期包含第 1 周周一／周四、第 2 周周一／周四共 4 个独立模板；严格保留提供的动作、组数、次数与休息时间。杠铃深蹲 65→67.5 kg（第 2 周备注状态良好可 70 kg），卧推 40→42.5 kg。RPE、自重、轻哑铃、单腿／单侧、6–8 次范围和屈膝版本均保留。没有明确负重的动作不预设重量。

开始训练时，固定重量优先采用当周计划；没有给定负重的动作按相同动作 ID 自动填入上次完成组重量。每个动作下方始终显示上次实际完成的各组。杠铃填写含杆总重，哑铃填写单只重量；空白表示自重／未设置。次数按每腿／每侧填写，两侧均完成后勾选一整组。哥本哈根平板用秒记录。重量可手动修改。

每次修改自动保存，包括未完成的训练；同一设备刷新后可以继续。单个设备建议只开一个窗口训练，避免多窗口写入冲突。

训练过程中，每个动作的记录表下方都有“添加一组”按钮。新增组沿用该动作上一组的重量与次数，保持未完成，可继续修改和勾选；进度、历史、负荷、曲线及备份均包含新增组。只影响本次训练，不更改模板，单个动作最多记录 30 组。新增组不会启动休息计时，完成勾选后才按该动作的休息时间启动。

## iPhone 安装与离线

1. 在 Safari 中打开 GitHub Pages HTTPS 地址。
2. 点“分享”→“添加到主屏幕”→“添加”。
3. 从主屏幕启动，保持联网，等顶部显示“离线已就绪”。
4. 开启飞行模式后再次打开，确认可以查看计划和记录训练。

应用通过 Workbox 预缓存 HTML、JS、CSS 与 PNG 图标，不依赖外部字体或 CDN。升级提供手动更新提示，避免训练中突然刷新。倒计时保存结束时间，后台暂停 JS 后，回到前台会重算剩余时间。后台通知需按下述步骤单独开启，离线时本地训练仍可用，但联网通知无法保证按时送达。

## 联网后台休息通知

1. iPhone 使用 iOS 16.4 或更新版本，从主屏幕启动已安装的 COURT（普通 Safari 标签页不支持此推送订阅流程）。
2. 打开“数据与设置 → 后台休息提醒”，点击“开启后台通知”，在系统弹窗里允许通知。
3. 点击“10 秒后测试通知”，切去看视频或锁屏，确认系统通知实际出现。未收到时检查设置 → 通知 → COURT 的允许通知、横幅、声音与专注模式。
4. 正式训练勾选一组或开始休息后，等待界面显示“已安排”，再切去后台。暂停、重置、选择休息预设或结束训练都会取消旧提醒；继续计时或完成下一组会替换旧提醒。

推送订阅设置只属于当前设备，不包含在训练备份中；换手机需重新授权。关闭后台通知会取消提醒并退订。网络失败会明确提示，恢复联网自动重试同步；取消时断网可能仍收到之前已安排的提醒，需联网重试取消。通知已进入系统推送链路后无法保证撤回。

提醒服务：`https://court-rest-push-wsx1997125.pages.dev`。入口通过 Cloudflare Pages service binding 调用 Workers，关闭 Workers 直连入口。Cloudflare SQLite Durable Object 为每个随机设备凭证设置一个一次性 alarm，避免依赖被 iOS 暂停的网页计时器。发送／取消后移除订阅地址和加密密钥；剩余状态最多一小时后删除。不会接收动作名、重量、组数、训练历史或备份文件。推送消息固定为“休息结束”，有效期 60 秒，临时错误最多重试两次；网络和系统通知策略可能引入延迟，不承诺秒级送达。

### 部署提醒服务

```powershell
pnpm exec wrangler login
pnpm push:deploy
```

配置位于 `push-server/wrangler.jsonc`，在自己的账户部署需修改 account_id、Worker 名称、允许来源与应用 URL，同时修改前端 `VITE_PUSH_API`（可通过构建环境变量覆盖）和 `push-server/gateway/wrangler.jsonc` 的项目名、service 绑定。新账户需先创建对应的 Pages 网关项目。首次部署脚本自动生成 VAPID 密钥，只将公钥写入配置，私钥通过 stdin 写入 Cloudflare Secret，不落文件、不提交 Git。之后重新部署复用密钥，不会让现有订阅失效。提醒服务独立部署，GitHub Actions 仍只构建和发布 PWA。测试命令 `pnpm test` 含提醒校验、加密、取消、乱序更新、重试及清理测试；`pnpm test:e2e` 含前端提醒流程与 Service Worker 处理测试；`pnpm test:push-runtime` 在实际 Workers runtime 中验证 SQLite alarm、加密发送与取消；`node scripts/smoke-push.mjs` 验证线上安排与取消，不向真实设备发通知。

## JSON 备份与迁移

在“数据与设置”导出完整 JSON，包含计划、历史、草稿与计时状态。恢复前校验应用标识、版本、动作、重量、组数与日期，然后显示覆盖确认。恢复替换全部本地数据，确认前可先备份当前记录。建议每周和升级前备份至“文件”。浏览器清理、卸载、隐私浏览或系统存储回收都可能导致本地数据丢失，持久存储请求不能代替备份。

换手机：旧设备导出 → 将 JSON 保存至“文件”或传到新设备 → 在新设备安装并启动主屏幕应用 → 设置中恢复。Safari 与主屏幕应用的存储环境可能不同，请在最终使用的主屏幕应用中恢复。

## 直接编辑训练模板

在训练页选择训练日，点击“编辑模板”；或在“数据与设置 → 训练计划”中点击对应模板的“编辑”。支持修改名称、周次、训练日、动作名称、器械、组数、次数／秒、每腿／每侧、重量、休息与说明，也支持添加、删除和排序动作。点击“保存模板”后自动写入本地数据库，离线可用；点击“取消”不保存草稿。

修改仅影响后续新建训练，已经开始的训练和历史记录保留当时的快照。调整同一动作会保留上次重量关联；如果改成另一种动作，请删除原动作再添加新动作，避免将两种动作的重量混在一起。模板也包含在完整 JSON 备份中。

计划导入支持 `{ "plans": [...] }` 或计划数组，也可先点“导出计划格式”再编辑 JSON；同一动作应保持稳定 ID，才能关联历史重量。导入计划不删除历史记录。

力量曲线只使用已结束训练中已完成组的最大实际重量（kg）；单次记录也会显示点。总负荷是完成组的重量 × 次数，哑铃乘 2，标记单侧／腿的动作再乘 2；自重和空白负重计 0，时间动作的自重不计负荷。这是记录口径，不是估算 1RM。

## GitHub Pages

工作流 `.github/workflows/deploy.yml` 在 main 推送后测试、构建并部署。仓库 Settings → Pages → Source 选择 **GitHub Actions**。资源 base 使用 `./`，支持仓库子路径；界面通过内部状态导航，不会出现路由刷新 404。

```powershell
git init -b main
git add .
git commit -m "Build basketball training PWA"
gh repo create basketball-training --public --source . --remote origin --push
```

公开仓库只提交源代码和内置计划，不提交备份、个人训练日志或密钥。托管地址变更会改变浏览器的本地存储来源，变更前先备份。

技术参考：[Vite GitHub Pages 部署](https://vite.dev/guide/static-deploy.html)、[MDN Service Workers](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)。
